# 0014. Hosting: Render (API) + Netlify (website) + Supabase, with the API forwarded under the website's address

Status: Accepted · Date: 2026-10-05

## Context
The store must be reachable from anywhere on free tiers without a card. The backend is a long-running Python program (FastAPI) in a Docker image (ADR 0012/0013); the website is static files; data and photos are in Supabase (Ireland). Safari on iPhone blocks cookies that a page receives from a *different site* ("third-party cookies"), which would silently break website sign-in if the website and the API sat on different domains.

## Decision
- **API on Render's free web service**, deployed from the Docker image via `render.yaml`, in **Frankfurt** (nearest Render region to the Ireland database). Migrations run at container start.
- **Website on Netlify** (static, free, deploys from GitHub).
- **The website forwards `/api/*` to the API** (a Netlify rewrite with status 200, i.e. a reverse proxy). The browser only ever talks to the Netlify address, so the login cookie is first-party and works on iPhone Safari. `BACKEND_URL` is therefore the Netlify address plus `/api`, and that is the Google callback registered in the Google console.
- **The mobile app uses a bearer token** (ADR 0013), so it is not affected by cookie rules and can call the API directly.
- **Free-tier sleeping is handled, not hidden:** an external free pinger keeps the service awake (one always-on free service fits the 750 monthly hours) and the clients show "waking the server" instead of an error.
- Secrets live only in Render's and Netlify's dashboards (and the local `.env`); `render.yaml` holds none, and the session secret is generated by Render.
- Free subdomains (`*.netlify.app`, `*.onrender.com`); a custom domain can be added later without code changes.

## Alternatives considered
- **API on Netlify/Vercel functions:** not a fit for a long-running FastAPI app with database pooling and file uploads.
- **Cloud Run:** generous free tier and no sleeping, but needs a billing card and more set-up.
- **Railway / Fly.io:** no longer free.
- **Different domains and `SameSite=None` cookies:** blocked by Safari's tracking prevention; unreliable.
- **A custom domain with the website and API as sibling subdomains:** also works (same registrable domain) but costs money and is not needed.
- **Token auth for the website too:** would need storing the token in JavaScript-readable storage, which is weaker than an httpOnly cookie.
- **Scheduled GitHub Actions as the keep-awake pinger:** a 10-minute schedule would use more of the free monthly minutes of a private repository than are available.

## Consequences
- (+) Free, no card, portable (Docker + static files), secure cookie model kept for the website; Safari-safe; clear secrets handling.
- (-) The first request after idle can take about a minute without the pinger; Netlify's forwarder has time and body-size limits (verified in Block 4); the Google callback address depends on the Netlify site name, so that name is chosen before Google is configured; free-tier terms can change.
